WiSIWireless-in-the-Loop Self-Improvement

Embodied agents can now rewrite their own programs from execution feedback. But the wireless link decides what that feedback shows and which rewrites pass the test. WiSI puts the network inside the improvement loop, and the agents that come out learn to communicate differently.

Beyond the simulator

Measured networks, unseen houses, a real vision model

The paper checks the main result three independent ways. Here is one example of each: the same evolved programs on a measured LTE throughput trace and in a house never used during development, and a real vision-language model answering from rendered images.

The idea

The network acts on the loop twice

A self-improving agent repeats one cycle: run the current program, show its execution logs to an LLM, let the LLM write candidate programs, test the candidates, keep the best. When the agent depends on a wireless link, that link shapes two steps of the cycle: the feedback the LLM learns from (EL) and the selection that decides which candidates survive (ES). WiSI controls the two separately.

Spatiotemporal channel

Indoor radio maps from house geometry (path loss, wall loss, shadowing), Rayleigh block fading and contention through the airtime share ρ. Uploads integrate the rate along the agent's own position and time.

Edge-assisted perception

A small on-device model or a stronger edge model reached over the link. Programs choose what to send: full frames or crops, at three resolutions, with their own timeouts and fallbacks.

LLM program improvement

The LLM rewrites the whole decision program, not a parameter vector. Children face the parent on fresh task batches; only strict improvements are kept, across four generations.

Where a program is improved decides how it holds up

The paths split after the first generation

+36.6 pp under congestion after generation one ([30.9, 42.1]), and the gap persists through generation four.

Feedback and selection both carry the network in

+23.1 pp from wireless feedback alone with selection already wireless ([16.8, 28.7]). Feedback changes what the LLM writes (compact code in 12 of 12 first responses, against 3 of 13 under ideal feedback); selection decides what survives.

Evolved programs learn to talk less

Programs improved via a network-blind loop typically need 13–16 uploads per task under congestion; programs improved via WiSI need 5–9. Rewriting beats tuning: 77.2% against 53.1% for parameter search (61.2% with 11× the budget).

Takeaways

Practical rules for improving connected agents

Improve where you will deploy

An ideal link hides the communication bottleneck, and the evolved program inherits that blind spot: 40.0% against 77.2% under congestion.

Wireless feedback, not only wireless tests

Realistic selection alone is not enough. Feedback from realistic execution changes which program structures the LLM proposes in the first place.

Moderate or mixed load transfers best

Moderate contention or a mix of ideal and congested tasks keeps ideal-link performance and generalizes to heavier load.

A simple channel model can be enough

A uniform model that keeps the radio map's rate distribution but not its spatial structure gives comparable programs (−1.2 points, [−4.6, 2.0]).

Code

Run it yourself

Code: github.com/NICE-HKU/WiSI. The release contains the simulator, the improvement loop, both pools of hand-designed programs and the experiment scripts. Fixed-program experiments and dry runs need no API key; the simulator is deterministic, so the reference rows of the main table reproduce exactly.

# install and test
pip install -r requirements.txt
python -m unittest discover -s tests

# fixed programs under Ideal and congested Radio-map
python scripts/run_fixed.py --run-id demo --agents s1_full_frame,s4_always_crop --cells A:R2,D:R4

# one improvement lineage without API calls, then the full study
python scripts/run_lineage.py --out outputs/study --cond D --regime R4 --dry-run
python scripts/run_study.py --plan configs/improvement.json --out outputs/study
python scripts/audit_study.py outputs/study
